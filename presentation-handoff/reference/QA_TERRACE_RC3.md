89개 instrumentation은 통과했지만 테스트가 만든 빈 prefs1개를 runner가 운영 파일로 분류해 보존 검사가 실패했다. 기존 운영3파일의 해시는 모두 같았다. 해당 빈 테스트 파일만 확인 후 정리하고 테스트 namespace/prefix 규칙을 고쳤다. 이후 대상15개와 최신 전체98개(실행97개·skip1개) 실행은 엄격 runner와 운영3파일 해시 비교까지 통과했다. 초기 runner 실패를 숨기거나 앱 데이터 손실로 단정하지 않는다.

## 4. API·배포 판정

Android에서 완료한 API 관측은 별도 opt-in 검사의 `blocked` 응답이다. 이후 데스크탑에서 새4링크의 `success`·상품명·가격·이미지 URL을 확인했다. **실제 폰 UI 등록은 진행 중이며 아직 완료가 아니다.** Android 자동 저장·이미지 표시·부분 응답 및 반환 가격의 옵션/회원/쿠폰 조건 확인은 관찰한 범위를 별도로 기록한다. 실패 시 원래 입력을 보존하고 직접 입력으로 이어지는 경로를 유지한다.

최종 **정확한 release APK**에서 인증된 계약 응답까지 확인하면 metadata를 `ConfiguredResponseVerified`, `realApiConnected=true`로 기록할 수 있다. 이는 상품 추출 성공을 뜻하지 않는다. `RealApiVerified`는 실제 상품 추출 성공을 확인했을 때만 사용한다. 시험용 토큰 내장이나 개발용 opt-in 검사만으로 release 검증을 완료하지 않는다.

원문 API 문서·실제 주소/키·기기 serial·원시 로그·백업은 공개 보고서와 Git에 포함하지 않는다. 내장 토큰이 추출 가능한 시험용 APK라는 배포 조건은 릴리스 노트에 명시한다.
