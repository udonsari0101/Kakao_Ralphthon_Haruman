상태: `target` — 디자인 확정, 구현 전. 이 폴더만으로 마당 탭을 구현할 수 있도록 요구사항·목업·자원을 모았다.

| 폴더 내용 | 설명 |
|---|---|
| `mockups/마당탭_테라스밭.png` | 확정 목업 (390×844, 2배 해상도) |

기존 캐릭터·흙더미·새싹·나무 그림은 [모아·토리 인계 폴더](../README.md)의 `assets/`에 있다.

## 1. 무엇을 만드나

기록 탭을 **“마당” 탭**으로 바꾼다. 사용자가 담은 물건 하나하나가 마당의 식물로 보이고, 결정 결과에 따라 모습이 바뀐다. 한 달을 **주(월–일) 단위의 계단식 밭(테라스)** 으로 나눠 위에서 아래로 쌓아 보여 준다.

| 물건 상태 | 마당 모습 | 자원 |
|---|---|---|
| 고민 중 (대기 시간 남음) | 도토리 흙더미 | `prop_acorn_buried` (기존) |
| 결정할 때 (`ready(now)`) | 새싹 + 반짝임, 노란 빛 강조 | `prop_sprout_ready` (신규) |
| 안 사기로 함 (`SKIP`) | 나무. 5만 원 미만 작은 나무, 5만–20만 원 큰 나무, 20만 원 이상 도토리 열린 나무. 가격 미정은 작은 나무 | `prop_tree_small` · `prop_tree_big` (기존), `prop_tree_fruit` (신규) |
| 사기로 함 (`BUY`) | 흙이 양옆에 쌓인 파인 구덩이 | `prop_hole` (신규) |

- 물건은 **추가한 날(`createdAt`)** 의 자리에 심기고, 결정이 나도 그 자리에 남아 모습만 바뀐다.
- 가격 미정 표시용 `prop_sign_unknown`은 주 상세·물건 상세에서 쓴다(월간 밭에는 그리지 않는다).
- 새 데이터 필드는 없다. 위치는 `createdAt`, 상태는 `decision`·`ready(now)`, 크기는 `priceWon`으로 계산한다.

## 2. 화면 구성 (위 → 아래)

목업: `mockups/마당탭_테라스밭.png`

1. **제목 줄**: “마당” + 기간 전환 `한 주 / 한 달` (기본 `한 달`).
2. **기간 이동**: `‹ 2026년 9월 ›`. 이번 달보다 미래로는 이동하지 않는다(오른쪽 버튼 비활성). 좌우 스와이프로도 이동.
3. **요약 카드**: 나무 수·아낀 금액 / 구덩이 수·구매 금액 / 고민 중 개수, 그 아래 소비 목표 게이지(목표를 설정한 경우만). 게이지 색: 0–69% 파랑, 70–89% 노랑, 90–99% 주황, 100% 이상 빨강.
4. **테라스 밭 목록**: 그 달에 걸친 주마다 한 층(보통 4–6층). 가장 아래가 가장 최근 주.
5. **캐릭터**: 결정할 새싹이 있으면 해당 주 근처에 토리(`mascot_tori_present`)와 말풍선 “새싹 N개가 기다려!”. 누르면 정리 시간.
6. 하단 탭: 보관함 · **마당** · MY.

## 4. 식물 배치 규칙 (`lay.py`)

주 안에서 **요일 자리 순서대로** 놓되, 물건이 몰린 날이 자리를 더 넓게 쓴다.

- 요일 자리의 너비 비율: 물건 `n`개인 날은 `min(n, 3)`, 빈 날은 `0.55`. 전체 너비를 이 비율로 나눈다.
- 한 날에 3개까지는 앞줄에 나란히. 4–6번째는 뒷줄(크기 78%, 10dp 위, 오른쪽으로 살짝 밀림)에 그려 깊이감을 준다.
- 한 날에 7개 이상이면 앞·뒷줄 6개만 그리고 그 자리에 `+N` 팻말을 붙인다.
- 같은 날 안의 순서는 `createdAt` 순.
- 기본 크기 44dp에 상태별 배율: 도토리 열린 나무 1.18, 큰 나무 1.08, 작은 나무 0.92, 구덩이 1.0, 새싹 0.98, 흙더미 0.86.
- 새싹은 노란 빛(drop shadow)으로 강조한다.

## 5. 기간 규칙

- 주는 **월요일 00:00 시작**, 기기 시간대 기준.
- 월간 보기의 층은 그 달의 날짜가 하루라도 포함된 주 전부다(예: 9월 1주 = 8.31–9.6). 층 안에는 그 주의 모든 날이 보인다.
- **요약 카드와 목표 게이지는 그 달 날짜만 집계**한다. 요약은 심은 날 기준, 목표 게이지는 사기로 결정한 날(`decidedAt`) 기준이다. 층의 금액 칩은 그 주 전체 기준이다.
- `한 주`를 고르면 한 페이지가 한 주가 된다. 위에 해당 주의 테라스 한 층을 크게 두고, 아래에 날짜별로 물건 카드(그림·이름·가격·결과)를 모두 나열한다(주 상세와 같은 구성).
- 기간 설정(`yard_period`: `WEEK` / `MONTH`, 기본 `MONTH`)은 MY에 두고 기존 설정 저장소에 추가한다. 소비 목표도 같은 기간 단위를 따른다.

## 6. 상호작용

| 동작 | 결과 |
|---|---|
| 층(팻말·흙 벽면) 누르기 | 그 주의 주 상세(날짜별 물건 카드 전체 목록) |
| 새싹 누르기 | 그 물건의 결정 화면 |
| 나무·구덩이·흙더미 누르기 | 물건 상세 |
| 토리·말풍선 누르기 | 정리 시간(결정할 물건 전체) |
| 좌우 스와이프, `‹ ›` | 이전·다음 기간 |

접근성: 층마다 “9월 4주, 나무 3그루 99,000원 아낌, 구덩이 2개 107,000원 구매, 결정할 새싹 8개”처럼 한 문장으로 읽히게 한다. 식물 하나하나는 “헤어 드라이어, 결정할 때” 형태.

## 7. 모션

| 상황 | 동작 | 모션 줄이기 설정 시 |
|---|---|---|
| 마당 진입 | 새로 돋은 새싹만 흙을 뚫고 올라옴 (scaleY 0→1, 360ms, 한 번) | 바로 표시 |
| 안 사기로 결정 직후 복귀 | 해당 새싹이 나무로 자람 (360ms) | 바로 표시 |
| 사기로 결정 직후 복귀 | 흙 알갱이가 튀고 구덩이가 드러남 (300ms) | 바로 표시 |
| 금액 칩·요약 | 처음 볼 때 숫자가 올라가며 표시 (400–650ms) | 최종값 |

한 번 재생한 변화는 물건 ID + 상태로 기억해 다시 재생하지 않는다. 데이터 저장은 연출과 무관하게 즉시 반영한다.

## 8. 구현 메모

- Compose: 층은 `Column` 안의 고정 높이 `Box`. 식물 위치는 `lay.py`와 같은 순수 함수(`layoutWeek(items, widthPx)` → 위치·크기 목록)로 계산해 단위 테스트한다.
- 기간 계산 순수 함수: `weekStart(time)`, `weeksOfMonth(year, month)`, `periodSummary(items, range)`.
- 자원: `assets/android-drawable/*.xml`을 `res/drawable/`에 복사. 기존 자원은 상위 인계 폴더의 `assets/android-drawable/`.
- 목업 수치는 `mockup-source/v.css`의 `.ter`, `.lip`, `.face`, `.sign`, `.dl` 규칙이 원본이다.

## 9. 완료 기준

- 9월 예시 데이터(37개, 13일 7개·26일 6개처럼 몰린 날 포함)에서 모든 물건이 잘리지 않고 그려진다(7개 이상인 날은 `+N`).
- 월간 5층이 360dp 폭 기기에서 스크롤로 모두 보이고, 층끼리 겹치지 않는다.
- 요약·층 금액 칩·목표 게이지가 규칙대로 집계된다(단위 테스트: 달 경계 주, 가격 미정, 예시 항목).
- `한 주`/`한 달` 전환과 기간 이동 후에도 같은 물건이 같은 자리에 있다.
- 결정 후 마당으로 돌아오면 새싹이 나무 또는 구덩이로 바뀌고, 연출은 한 번만 재생된다.
- 글꼴 1.3배에서 팻말·칩·요일 글자가 겹치지 않는다(칩은 줄바꿈 허용).

## 10. 범위 밖

- 보관함 헤더의 모아 볼 단계, 결정 화면의 목표 미리보기, 목표 초과 반응, 마당 일기 리포트는 별도 작업이다(설계: [저장 데이터 시각화 정리안](../guides/storage-visualization.md)).
- 홈 무작위 배치, 날짜 달력 칸 배치는 검토 후 채택하지 않았다.
