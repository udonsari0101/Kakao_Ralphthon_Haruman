# 구현 요구사항: 모아·토리 캐릭터 상호작용

상태: `target` — 구현되지 않았다. 현재 `apk-project`(Compose, 로컬 저장)의 화면 구조와 데이터 계약은 유지하고, 그 위에 캐릭터 레이어와 **정리 시간**을 더한다. 기준 코드는 [현재 구현](../../architecture/haruman/current.md)과 [코드 지도](../../maps/haruman.md)다.

함께 읽을 것: [캐릭터 설정](guides/character-bible.md) · [카피 덱](guides/copy-deck.md) · [토큰·모션 명세](guides/motion-and-tokens.md) · [미리보기(자원 시트·화면 목업)](preview.html)

## 1. 목표와 성공 기준

대회 심사에서 **3분 시연 안에 캐릭터와 함께 담고 → 기다리고 → 정리하는 경험**이 한 번에 보이게 한다.

| 목표 | 성공 기준 |
|---|---|
| 담는 순간이 즐겁고 빠르다 | 공유 → 저장까지 기존과 같은 탭 수. 저장 직후 1초 이내의 모아 연출과 캐릭터 문구가 보인다 |
| 기다리는 시간이 보인다 | 보관함 행과 상세에서 대기 진행이 도토리 3단계로 보인다. 숫자 남은 시간도 그대로 보인다 |
| 다시 보는 순간이 기억에 남는다 | 결정할 항목이 2개 이상이면 정리 시간에서 카드 넘기기로 한 번에 정리하고, 결과 카드와 축하가 한 번 재생된다 |
| 어느 선택이든 보상받는다 | 보내기는 절약 금액과 나무, 사기로 하기는 모아의 칭찬으로 끝난다. 비난 문구가 없다 |
| 기존 기능이 깨지지 않는다 | 기존 JVM·Compose 테스트 통과, 예전 `haruman_local_v1` 데이터가 그대로 읽힌다 |

## 3. 데이터 변경 (최소)

- `WishItem`에 `desire: Desire? = null` 추가. `enum class Desire { FIRE, LIKE, MEH }` (🔥 엄청 / 🙂 꽤 / 🤔 글쎄).
- JSON 키 `desire`는 선택값. 쓰기: `null`이면 `JSONObject.NULL`. 읽기: 키가 없거나 `null`이거나 모르는 값이면 `null`. **기존 레코드는 그대로 읽혀야 한다.**
- 예시 항목에는 `desire`를 1–2개만 넣어 정리 시간 문구 분기를 시연할 수 있게 한다(`sample-headphones` = `FIRE`, `sample-lamp` = `MEH`).
- 결정·연장 규칙은 기존 `decide()`·`extend()`를 그대로 쓴다. 새 결정 상태를 만들지 않는다.
- 정리 세션 요약(보낸 개수·합계·사기로 한 개수·다시 묻은 개수)은 저장하지 않고 화면 상태로만 가진다.
- 도토리 단계 계산은 순수 함수로 `LocalStore.kt` 옆에 둔다: `fun acornStage(item, now): AcornStage` — `ready(now)`이면 `READY`, `progress(now) >= 0.5f`이면 `SPROUT`, 아니면 `BURIED`. 결정된 항목은 `null`.

## 4. 화면별 요구사항

### R1. 캐릭터 공통 컴포넌트 (P0) — 새 파일 `ui/mascot/`

- `enum class MascotPose(@DrawableRes val res: Int)` — [캐릭터 설정의 포즈 표](guides/character-bible.md#상태포즈와-자원-매핑) 10개.
- `@Composable fun Mascot(pose, modifier, size: Dp, breathing: Boolean = true, onClick: (() -> Unit)? = null)` — `painterResource(pose.res)`로 그린다. 포즈 전환은 MO-2, 호흡은 MO-1. `contentDescription`은 “햄스터 모아”, “다람쥐 토리”.
- `@Composable fun SpeechBubble(text, modifier, tail: BubbleTail)` — 둥근 16dp 면, 꼬리 방향(왼쪽/아래), 최대 2줄, MO-4. 접근성: 캐릭터와 말풍선을 한 노드로 묶어 “모아: {문장}”으로 읽는다.
- `MascotCopy.kt` — [카피 덱](guides/copy-deck.md) 상수와 `pick(key, seed)` 헬퍼. 시드는 화면 진입 시 한 번 정한다.
- `LocalReduceMotion` CompositionLocal — [모션 규칙](guides/motion-and-tokens.md#4-모션) 참고.
- 자원: `assets/android-drawable/*.xml`을 `app/src/main/res/drawable/`에 그대로 복사한다. 파일명 변경 금지(문서와 연결됨).

### R2. 온보딩 (P0) — `Screens.kt` `Onboarding`

- 가운데 그림(파란 상자 + 두 카드)을 `scene_duo_onboarding`(너비 300dp, 좁은 화면 85%)으로 교체한다. 기존 Instagram·Coupang 카드 2장은 장면 위 좌상·우하에 그대로 띄운다.
- 제목·설명·`시작하기` 버튼·`testTag("onboarding_start")` 유지.
- 설명 아래에 캐릭터 역할 2줄(모아 머리 24dp + 문장, 토리 머리 24dp + 문장)을 추가한다. 문장은 카피 덱 “온보딩”.

### R3. 보관함 헤더 “모아의 방” (P0) — `Screens.kt` `VaultScreen`

- 제목 행과 필터 사이에 `MascotStage` 카드(높이 112dp, 모서리 20dp)를 넣는다. 기존 두 줄 요약(“지금 N개…”, “이번 달 …”)은 카드 안 오른쪽으로 옮기거나 카드 아래에 그대로 둔다 — 정보는 잃지 않는다.
- 왼쪽에 모아 88dp: 보관(`PENDING`) 0개 `MOA_SLEEP`, 1–4개 `MOA_IDLE`, 5개 이상 `MOA_STUFFED`. 말풍선은 카피 덱 “보관함 헤더”.
- 결정 필요(`ready`) 항목이 1개 이상이면 오른쪽 아래에서 토리 56dp가 도토리를 들고 등장(MO-2)하고, 카드 하단에 CTA `정리 시간 시작 · N개`(48dp 이상, `testTag("start_review")`)를 보여 준다. 1개일 때도 정리 시간으로 들어간다.
- “다시 결정할 시간이에요” 섹션 제목 오른쪽에도 같은 진입 텍스트 버튼 `한 번에 정리 ›`를 둔다(2개 이상일 때).
- 필터·목록·`+` 버튼·예시 안내 문구는 유지한다.

### R4. 추가 시트와 “받았다” (P0) — `AddSheet.kt`, `HarumanApp.kt`

- 시트 제목 줄 왼쪽에 모아 56dp(`MOA_RECEIVE`, 호흡 없음)와 말풍선. 공유로 열리면 “링크 받았어!” 문구.
- 대기 시간 선택 위에 선택 입력 “얼마나 갖고 싶어?” 칩 3개(🔥 엄청 / 🙂 꽤 / 🤔 글쎄). 다시 누르면 해제. `testTag("desire_fire|like|meh")`. 저장 가능 조건(`canSave`)은 바꾸지 않는다.
- `onSave` 시그니처에 `desire: Desire?`를 추가하고 `WishItem` 생성 시 넣는다. 두 저장 버튼 모두 전달.
- 저장이 확정되면 시트를 닫고 보관함 위에 MO-5 “받았다” 오버레이를 띄운다(`Box` 최상단, 입력 차단 없음, 탭하면 종료). 그 뒤 스낵바를 카피 덱 “저장 직후”로 바꾼다. 중복 링크·지원하지 않는 공유 스낵바도 카피 덱 문구로 바꾼다.
- 보관함 헤더의 모아 포즈는 저장 직후 새 개수 기준으로 갱신된다(5개 도달 시 `STUFFED`).

### R5. 도토리 대기 표시 (P0) — `Screens.kt` `ProductRow`, `DecisionScreens.kt` `DetailScreen`

- `ProductRow` 오른쪽 열: 보류 중이면 시계 아이콘 자리에 `acornStage` 아이콘 28dp(`prop_acorn_buried`/`sprout`/`ready`). 기존 남은 시간 텍스트·`결정 필요` Pill·`결정하기 ›`는 유지한다. 단계가 바뀌는 순간만 MO-6.
- `DetailScreen` 보류 상태: 큰 남은 시간 숫자 아래, 진행 막대 위에 3단계 가로 표시(각 40dp 아이콘 + “묻음 · 새싹 · 캐기” 라벨, 현재 단계 강조, 지난 단계 100%, 다음 단계 40% 불투명). 진행 막대와 “%” 문구는 유지.
- 상세 상단 오른쪽(상품명 영역 아래)에 토리 72dp + 말풍선: 카피 덱 “대기 중 상세”.

### R6. 정리 시간 (P0, 핵심 장면) — 새 파일 `ui/ReviewScreen.kt`, 새 route `"review"`

진입: R3의 CTA 또는 섹션 버튼. 대상은 진입 시점의 `ready` 항목 목록(오래된 순)으로 고정한다(세션 도중 새로 준비된 항목은 다음 세션).

화면 구성(위→아래):
1. 상단 바: 뒤로가기, 진행 `2 / 5`, `testTag("review_progress")`.
2. 토리 96dp(`TORI_PRESENT`) + 말풍선(카피 덱 “정리 시간”; 저장 때 `desire`에 따라 분기).
3. 카드 스택: 맨 위 카드 + 뒤 카드 최대 2장(scale 0.95/0.90, 아래로 8dp씩). 카드 = 상품 그림(`ProductArtwork`, 이후 스크린샷 입력이 생기면 이미지), 상품명, 가격(`money`), 플랫폼, “{date}에 담음”, 저장 때 갖고 싶은 정도 칩. 카드 위 좌우 스탬프 라벨 “안 살래요”(초록)·“살래요”(파랑)는 드래그 진행에 따라 나타난다.
4. 하단 버튼 3개(모두 48dp 이상): `안 살래요`(약한 버튼) · `조금 더`(텍스트 버튼, `{defaultHours}` 연장) · `살래요`(주 버튼). `testTag("review_skip|later|buy")`. **스와이프 없이 버튼만으로 모든 동작이 가능해야 한다.**

동작:
- ← 스와이프 또는 `안 살래요` → `decide(item, SKIP, now)` 즉시 저장 → 토리 `WAVE` + 가격이 있으면 “+{price}” 떠오름(MO-11 축소판, 600ms).
- → 스와이프 또는 `살래요` → `decide(item, BUY, now)` 즉시 저장 → 모아 `HAPPY` 잠깐 등장. 원본 링크 열기는 결과 카드에서 한꺼번에 제공(세션 흐름을 끊지 않음).
- `조금 더` → `extend(item, defaultHours, now)` 즉시 저장 → MO-10.
- 판정·다음 카드 모션은 MO-7~MO-9. 연타로 같은 카드가 두 번 결정되지 않게 판정 중 입력을 막는다.
- 모든 카드를 처리하면 같은 화면에서 **정리 결과 카드**로 전환: 토리 `CHEER` 140dp, 제목 “오늘의 정리 끝!”, 요약 한 줄, 아낀 금액 카운트업(MO-11), confetti 1회(MO-12, 보낸 것이 있을 때만). 버튼: `결과 공유하기`(기존 내보내기와 같은 `ACTION_SEND` 텍스트, 카피 덱 “공유 텍스트”), `사기로 한 상품 보기`(BUY가 있을 때, 기록 탭으로), `보관함으로`.
- 뒤로가기: 세션 도중이면 이미 결정한 항목은 저장된 상태로 보관함에 돌아간다(확인 대화상자 없음).
- 합계 규칙은 기존과 같다: 가격 `null`은 합계 제외, 예시 항목은 결과 카드에 “예시 포함” 작은 문구.
- 기존 `decide` route(단일 항목 결정)는 그대로 둔다. 목록에서 한 항목을 누르면 기존 흐름, 한꺼번에 정리할 때만 정리 시간.

### R7. 결과 화면 캐릭터 (P0) — `DecisionScreens.kt` `ResultScreen`

- 64dp 아이콘 상자를 캐릭터 120dp로 교체: 포기 `TORI_CHEER`, 구매 결정 `MOA_HAPPY`. 캐릭터 아래 말풍선은 카피 덱 “결과 화면”.
- 포기 시 “이번 달 쓰지 않기로 한 금액” 숫자에 MO-11, confetti MO-12 1회(이벤트 ID = `item.id + decidedAt`).
- 문구·버튼·`testTag("result_home")` 유지.

### R8. 절약 숲 (P0) — `Screens.kt` `HistoryScreen`

- 이번 달 요약 카드 안, 구분선 아래에 “이번 달 절약 숲” 줄을 추가한다: 이번 달 `SKIP` 항목마다 나무 1그루(가격 5만 원 이상 `prop_tree_big`, 미만·가격 없음 `prop_tree_small`), 결정 시각 순, 한 줄 6그루 최대 2줄, 넘치면 `+N그루`. 나무를 누르면 그 항목 상세.
- 숲 오른쪽 끝에 토리 48dp(`TORI_IDLE`)와 카피 덱 “기록·절약 숲” 문구. 0그루면 빈 흙더미(`prop_acorn_buried`)와 안내 문구.
- 새로 생긴 나무만 MO-13으로 자란다(마지막으로 본 나무 수를 `rememberSaveable`로 기억; 영속 저장 불필요).
- 기존 합계·개수·최근 결정 목록 유지.

### R9. 빈 상태·스낵바 말투 (P0)

- `EmptyState`에 `pose: MascotPose? = null` 인자를 추가해 파란 상자 아이콘 대신 캐릭터 64dp를 쓴다: 보관함 비었음 `MOA_SLEEP`, “아직은 고민할 시간” `TORI_BURY`, 기록 없음 `TORI_IDLE`.
- 스낵바 문구는 카피 덱으로 교체한다. 시스템 오류성 문구(“링크를 열 수 있는 앱을 찾지 못했어요” 등)는 해요체 유지.

### R10. 되돌리기 (P1)

정리 시간에서 판정 직후 4초간 스낵바 `되돌리기`. 누르면 해당 항목을 **판정 전 객체로 복원 저장**하고 카드를 스택 맨 위로 되돌린다(MO-9 역방향), 요약 집계도 되돌린다.

### R11. 캐릭터 탭 반응 (P1)

보관함 헤더·정리 결과·기록의 캐릭터를 누르면 MO-3 + 카피 덱 “탭 반응” 중 하나. 연속 탭은 300ms 간격 제한.

### R12. 결정 화면 토리 (P1) — `DecideScreen`

상품 그림 104dp 오른쪽 위에 토리 64dp(`TORI_PRESENT`)가 걸치게 두고, “{date}에 저장했어요” 줄 아래 `desire` 칩(있을 때)과 카피 덱 “정리 시간” 분기 문장을 말풍선으로 보여 준다. 버튼 구성은 유지.

### R13. MY 캐릭터 설정 (P1) — `MyScreen`

“캐릭터” 섹션: `캐릭터 말풍선 보기`(켜짐 기본), `캐릭터 움직임 줄이기`(꺼짐 기본, 켜면 `LocalReduceMotion`을 true로). `LocalStore`에 Boolean 2개 추가(`mascot_bubbles`, `mascot_reduce_motion`), 없으면 기본값.

### R14–R16 (P2)

- R14 대기 완료 알림: 현재 앱에 알림이 없다. 넣는다면 저장 시 `cooldownUntil`에 맞춘 WorkManager 일회 작업, Android 13+ `POST_NOTIFICATIONS` 권한 요청은 첫 저장 직후 모아 말풍선으로 이유를 설명한 뒤. 문구는 카피 덱 “알림”. 알림을 누르면 정리 시간으로.
- R15 정리 결과 이미지 공유: 결과 카드를 비트맵으로 그려 `ACTION_SEND` 이미지 공유.
- R16 마일스톤 배지: 첫 보내기, 누적 10만 원, 나무 10그루에서 한 번씩 토리 `CHEER`와 배지.

## 7. 검증

- 단위: `desire` 없는 예전 JSON 읽기, `desire` 왕복, 모르는 값 → `null`; `acornStage` 경계(0.49/0.5/ready/결정됨); 정리 세션 요약 합계(가격 `null` 제외, 예시 표시).
- Compose UI: 보관함 개수별 모아 포즈(0/1/5개), `start_review` 노출 조건, 정리 시간에서 버튼만으로 SKIP·BUY·연장 → 저장 상태와 결과 카드 숫자, 뒤로가기 시 부분 결정 보존, `desire` 칩 선택·해제 후 저장.
- 기기: 320/360/412dp 폭과 글꼴 1.3/2.0배에서 헤더·카드·버튼 잘림 없음, 스와이프 임계값·되돌아감, 애니메이션 배율 0에서 정적 전환, 회전 시 축하 재재생 없음, 벡터 렌더링 품질(특히 외곽선 두께).
- 회귀: 기존 테스트 전부, 공유 수신 흐름, 기존 `decide` route.

## 10. 제약과 위험

- 벡터 자원은 이 폴더의 생성기로 만들었고 브라우저 렌더링만 확인했다. Android 기기 렌더링은 구현 1단계에서 확인해야 한다.
- 현재 앱은 파랑 라이트 고정이다. 목표 설계의 빨강·다크 테마 작업과 동시에 진행하면 `MascotStage`·말풍선 토큰만 테마에 연결한다.
- 스크린샷 입력(목표 설계)이 들어오면 정리 카드·상세의 `ProductArtwork` 자리를 이미지로 바꾼다. 캐릭터 요구사항은 영향받지 않는다.
- 캐릭터 연출이 반복 사용을 방해하지 않도록 모든 연출은 탭으로 끝낼 수 있고, 3회 이상 본 “받았다” 연출은 짧게(450ms) 줄이는 것을 권장한다(P1, 횟수는 메모리 보관).
